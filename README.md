# Крутые магические битвы

## Запуск и команды

Python-бэкенд использует PostgreSQL, Redis для кэша каталога и MinIO для картинок.
Фронтенд — React/TypeScript/Vite. Команды выполняются из корня репозитория.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-testing.txt
cp env.example .env
make infra-up
```

Для PostgreSQL из Docker задайте в `.env`:
`DATABASE_URL=postgresql+psycopg://cmb:cmb@localhost:5433/cool_magic_battles`.
Для локального PostgreSQL оставьте URL из env.example и предварительно создайте БД
(вариант установки: `sudo bash scripts/setup_postgres_native.sh`).
Затем примените схему и добавьте демонстрационные данные:

```bash
make db-migrate
make db-seed
make upload-default-image
make run-api
```

API: `http://localhost:8000/docs`. В другом терминале:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс: `http://localhost:5173`. Для загрузки картинок после запуска API:
`make upload-card-images DIR=assets/cards`. Консольный интерфейс:
`PYTHONPATH=src python src/main.py`.

`make help` перечисляет команды управления инфраструктурой, миграциями,
отладкой и тестами. `make db-reset`, `db-reseed`, `db-truncate*` изменяют
данные выбранной в `.env` базы; для тестирования используйте отдельный стенд ЛР №2.

## Скрипты запуска и отладки

| Скрипт | Назначение / команда |
|---|---|
| `scripts/db.py` | Миграции, начальные данные, исправление связей картинок; `make db-*` |
| `scripts/setup_postgres_native.sh` | Установка локального PostgreSQL без Docker |
| `scripts/upload_default_image.py` | Загрузка картинки по умолчанию; `make upload-default-image` |
| `scripts/upload_card_images.sh` | Сопоставление названий карт с файлами и загрузка; `make upload-card-images DIR=assets/cards` |
| `scripts/test_trigger.sh` | Ручная диагностика триггера валидации; `make test-trigger` |
| `scripts/test_procedure.sh` | Ручная диагностика покупки карты; `make test-procedure` |
| `scripts/test_roles.sh` | Ручная диагностика прав ролей PostgreSQL; `make test-roles` |
| `scripts/test_minio.sh` | Ручная диагностика загрузки через API и MinIO; `make test-minio` |
| `scripts/testing/` | Изолированный стенд лабораторной по тестированию: runner, данные, сценарий, отчёты и восстановление |

Ручные `test_*.sh` работают с запущенными локальными сервисами и могут изменять
данные: карты, эхо игрока, роли и изображения. Они выводят результаты операций
для отладки и не заменяют автоматические проверки ЛР №2 с восстановлением baseline.
Для них нужны применённые миграции и начальные данные; для MinIO также запущенный
API. `AUTH_USER_ID` задаёт UUID мастера (по умолчанию мастер из `make db-seed`),
`API_BASE_URL` — URL API, `MINIO_MC_HOST` — адрес с учётными данными для mc внутри
Docker-сети, `DOCKER_NETWORK` — имя этой сети.

## Структура

- `src/api/` — REST API и зависимости запросов.
- `src/application/`, `src/domain/` — сценарии, игровые правила и сущности.
- `src/infrastructure/` — SQLAlchemy, Redis, MinIO и консольный интерфейс.
- `src/config/config.yaml`, `env.example` — настройки и переменные окружения.
- `alembic/`, `scripts/db.py` — миграции и обслуживание PostgreSQL.
- `src/tests/` — существующие тесты; `tests_lab2/`, `scripts/testing/` — стенд ЛР №2.
- `frontend/` — веб-интерфейс; `assets/cards/` — исходные картинки карт.
- `docs/`, `img/`, `report/` — схемы, иллюстрации и материалы курсовой.

Redis кэширует только каталог (`cmb:catalog:cards:v1`, `cmb:catalog:card_types:v1`);
TTL задаёт `REDIS_CATALOG_TTL_SECONDS`. Изменения каталога сбрасывают кэш.
Игровое состояние хранится в PostgreSQL. При недоступном Redis чтение идёт из БД.


**Проект** представляет собой компьютерную реализацию настольной колодостроительной игры "Эпичные схватки боевых магов:
Крутагидон". Крутые магические битвы сохраняют механики битв, накопления мощи и карт оригинальной игры.

**Предметной областью проекта** является цифровая реализация карточной колодостроительной игры. В рамках системы игроки
участвуют в игровых сессиях, используют карты различных типов (атака, защита, добор, исцеление, ручность, мощность),
приобретают новые карты из общего банка и взаимодействуют друг с другом посредством игровых действий.
> Основными сущностями предметной области являются:
> * пользователи;
> * ировые партии;
> * игроки в партии;
> * карты;
> * колоды игроков;
> * рынки карты;
> * игровые действия. изображение карты.

| Решение              | Онлайн мультиплеер | Колодостроение | Открытая система карт |
|----------------------|--------------------|----------------|-----------------------|
| Tabletop Simulator   | ✔                  | ✔              | ✔                     |
| Hearthstone          | ✔                  | ✖              | ✖                     |
| Dominion Online      | ✔                  | ✔              | ✖                     |
| Предлагаемая система | ✔                  | ✔              | ✔                     |

**Актуальность** проекта заключается в том, что настольная игра пользуется популярностью, но не всегда есть возможность
разложить карты и полноценно сыграть. Компьютерная версия дает возможность играть "на коленке" без привязки к столу или
колоде.

## Пользовательские сценарии

- Начало игры:
    - Пользователь заходит в систему
    - Пользователь выбирает "Создать игру"
    - Система создает новую игровую сессию
    - Пользователь становится первым игроком в сессии
    - Система ожидает присоединения остальных игроков
- Покупка карты:
    - Игрок получает на руку карты
    - Игрок разыгрывает карты с руки в произвольном порядке в любом количестве
    - Система подсчитывает мощь, накопленную игроком за разыгранные карты
    - Пользователь решает купить карты, выбирает из банка карту для покупки
    - Система проверяет, что мощи игрока хватает для покупки карты
    - Если хватает, карта удаляется из банка и добавляется в колоду сброса игрока
- Атака и защита:
    - Игрок 1 разыгрывает в свой ход карту атаки
    - Игрок 1 выбирает атаковать игрока 2
    - Игрок 2 может вне своего хода сыграть карту защиты от атаки
    - Если игрок 2 не играет защиту, то атака проходит, игрок 2 теряет очки здоровья
- Смерть игрока
    - Игрок 1 разыгрывает в свой ход карту атаки на 15 очков здоровья
    - Система предлагает Игроку 2 защититься
    - Игрок 2 отказывается от защиты (либо не имеет карт защиты)
    - Система проверяет оставшееся количество ОЗ Игрока 2 (7 ОЗ); так как здоровья осталось меньше, чем наносимый урон,
      то Игрок 2 умирает на этом ходу
    - Система регистрирует смерть Игрока 2, начисляет ему "памятку о бренности бытия", отмечающую смерть в игре, после
      этого устанавливает количество ОЗ Игрока 2 в дефолтное значение
    - Система проверяет, остались ли не присужденные никому памятки о бренности бытия. Если остались, то игра
      продолжается, иначе игра заканчивается
- Победа в игре
    - Система регистрирует последнюю игровую смерть (все памятки присуждены игрокам)
    - Проводится подсчет набранных очков крутости (или же победным очкам игры) для каждого игрока (по "очкам крутости"
      каждой карты в колоде игрока и по количеству памяток о бренности бытия, присужденных игроку)
    - Игрок, набравший больше всего очков крутости, объявляется победителем игры
    - В случае ничьи по очкам крутости, побеждает игрок с наибольшим количеством купленных карт
    - В случае ничьи по очкам крутости и количеству купленных карт, побеждает игрок с наибольшим количеством карт
      случайно выбранного типа
    - Если опять ничья, то победитель определяется путем сражения между игроками (например, камнь-ножницы-бумага или
      дуэль на мечах)

## Игровые термины


### Player/Игрок

* **Health points/Health/HP/Очки здоровья/Здоровье/ОЗ**
  Количество урона, которое игрок может выдержать, прежде чем умереть. Когда очки здоровья игрока достигают нуля, он умирает и возрождается с полным здоровьем (по умолчанию 20).

* **Echo points/Echo/EP/Очки Эхо/Эхо/ОЭ**
  Накапливаемые очки, которые игрок получает в результате розыгрыша карт. Могут быть потрачены на покупку новых карт из колоды рынка. Каждый ход сбрасываются. В начале игры "собственное" количество эхо равно 0, но может быть увеличено с помощью эффектов карт.

* **Memento of Mortaliy/Memento/Memo/MM/Памятка о бренности бытия/Памятка/ПББ**
  игровой элемент, выполняющий роль индикатора смертей в игре. В начале каждой партии определяется общее количество памяток (по умолчанию количество игроков * 4). Каждый раз, когда игрок умирает, он получает памятку. Когда все памятки расходованы, игра заканчивается. Каждая памятка отнимает у игрока определенное количество очков крутости.

* **Cool Points/CP/Очки крутости/ОК**
  очки, которые игрок получает вместе с купленными картами. В конце игры очки крутости карт суммируются со штрафами за памятки о бренности бытия и определяют победителя.
  >Чем больше очков крутости, тем круче игрок. В случае ничьей по очкам крутости, побеждает игрок с наибольшим количеством купленных карт. Если и по количеству купленных карт ничья, то побеждает игрок с наибольшим количеством карт случайно выбранного типа. Если и по этому показателю ничья, то победитель определяется путем сражения между игроками (например, камень-ножницы-бумага или дуэль на мечах).

### Card/Карта (здесь же типы карт)
* **Action/Effect/Действие/Эффект**(он же дйствие в типе карты)
  действие, которое выполняется при розыгрыше карты. Может быть атакой, защитой, добором карт, увеличением руки или базового количество эхо игрока.
* **Power/Сила**
  числовое значение, определяющее силу действия карты (количество наносимого урона, количество добираемых карт и т.д.)
* **Cost/Цена**
  количество очков эхо, необходимое для покупки карты из колоды рынка
* **Cool points/Очки крутости**
  количество очков крутости, которая карта приносит игроку
* **Шаблон розыгрыша карты**
  Способ, которым надо её разыграть. Варианты:
  - regular -- просто выложить на стол во воремя своего хода
  - on-top -- \[только защита\] вне своего хода, когда под атакой, положить карту на верх своей колоды добора, чтобы применить эффект защиты
  - discard -- \[только защита\] вне своего хода, когда под атакой, сбросить карту из руки в личный сброс, чтобы применить эффект защиты
  - banish -- \[только постоянные\] во время своего хода сбросить карту в общий сброс, чтобы применить эффект постоянного действия

### Колоды/Decks
* **[game_]deck/колода рынка** -- общая колода карт, из которых пополняется рынок; хранится взакрытую (т.е. рубашкой вверх)
* **market/рынок** -- открытая колода карт, доступных для покупки игроками; хранится открытой (т.е. картинкой вверх)
* **banish_deck/общий сброс** -- колода карт, которые были сброшены в процессе игры, карты не могут вернуться в колоды игроков; хранится взакрытую (т.е. рубашкой вверх)
* **hand/рука** -- колода карт, находящихся на руке у игрока т.е. карты, которые игрок может разыграть во время хода; хранится открытой для конкретного игрока и закрытой для остальных игроков
* **table/стол** -- колода карт, разыгранных игроком на стол во время его хода; хранится открытой для всех игроков
* **draw_deck/player_deck/колода добора** -- колода карт игрока, из которой он добирает карты в руку; хранится взакрытую (т.е. рубашкой вверх)
* **discard/сброс игрока** -- колода карт, которые были сброшены игроком в процессе игры, перемешиваются и становятся колодой добора, когда игрок не может набрать из колоды добора руку; хранится открытой колодой (т.е. видно только последнюю сброшенную карту)
